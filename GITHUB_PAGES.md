# Публикация демо на GitHub Pages — пошагово

Инструкция для варианта «без командной строки». Время — 10–15 минут.
Итог: постоянная ссылка вида `https://<логин>.github.io/doctor-catalog/`,
которая работает всегда, бесплатно, с HTTPS и установкой PWA на Android/iPhone.

Что понадобится: браузер, email, архив `nutricare_demo_site.zip` (лежит в корне рабочей папки).

---

## Шаг 1. Аккаунт GitHub

1. Открыть <https://github.com> → **Sign up**.
2. Ввести email, пароль, придумать username (он попадёт в адрес сайта — например `ivanov-md`).
3. Подтвердить email (код из письма).
4. Войти в аккаунт.

Если аккаунт уже есть — перейти к шагу 2.

---

## Шаг 2. Создать репозиторий

1. Открыть <https://github.com/new>.
2. **Repository name:** `doctor-catalog` (можно любое, латиницей, без пробелов).
3. **Description:** `Демо приложения Приложение для врачей — каталог детских смесей для врачей`.
4. **Public** — обязательно (на бесплатном тарифе GitHub Pages работает только
   для публичных репозиториев).
5. Галочки «Add a README file», «Add .gitignore», «Choose a license» — **не ставить**.
6. Нажать **Create repository**.

Откроется пустой репозиторий с подсказками — это нормально.

---

## Шаг 3. Загрузить файлы сайта

1. Распаковать `nutricare_demo_site.zip` в отдельную папку. Внутри должно быть:
   ```
   index.html
   manifest.webmanifest
   sw.js
   privacy.html
   README.md
   .nojekyll
   css/
   js/
   assets/
   icons/
   ```
2. В репозитории нажать **Add file → Upload files**.
3. Перетащить **содержимое** папки (все файлы и папки, а не саму папку
   `nutricare_demo_site`), либо нажать **choose your files** и выбрать их.
4. Дождаться, пока файлы загрузятся (44 файла, ~1 МБ), затем внизу нажать
   **Commit changes**.

Проверка: в корне репозитория должен быть виден `index.html`.
Если видно папку `nutricare_demo_site` — файлы загрузились на уровень глубже,
и сайт не заработает. В этом случае: удалить папку (⋯ → Delete directory),
и повторить загрузку, перетащив именно содержимое.

> `.nojekyll` — скрытый файл. Если при загрузке он не появился, создайте его вручную:
> **Add file → Create new file**, имя `.nojekyll`, содержимое пустое → **Commit changes**.
> Он отключает лишнюю обработку Jekyll. Для этого проекта не критичен, но полезен.

---

## Шаг 4. Включить GitHub Pages

1. В репозитории открыть вкладку **Settings** (вверху справа).
2. В левом меню — **Pages**.
3. Блок **Build and deployment**:
   - **Source:** `Deploy from a branch`;
   - **Branch:** `main`, папка `/ (root)`;
   - нажать **Save**.
4. Подождать 1–3 минуты и обновить страницу. Сверху появится:
   `Your site is live at https://<логин>.github.io/doctor-catalog/`

---

## Шаг 5. Проверить приложение

1. Открыть ссылку на компьютере — должен появиться экран приветствия «Приложение для врачей».
2. Быстрый вход без регистрации добавьте к ссылке:
   `https://<логин>.github.io/doctor-catalog/?demo=1#/home`
3. Открыть на Android в Chrome → меню ⋮ → **«Установить приложение»**
   (или «Добавить на главный экран»). Иконка появится на рабочем столе.
4. Проверить разделы: Ассортимент (24 карточки), Памятки (PDF открываются),
   Алгоритм выбора (92 ветки), Профиль.
5. Демо-доступ, если попросят логин: `doctor` / `doctor1234`,
   код доступа `NTL-DOCTOR-2026`.

---

## Шаг 6. Как обновлять сайт

Любое изменение файлов в репозитории автоматически пересобирает сайт (1–2 минуты):

- **Правка текста:** открыть файл (например `js/data.js`) → карандаш ✏️ → изменить →
  **Commit changes**.
- **Замена файла:** **Add file → Upload files** → перетащить новую версию файла с тем же
  именем → **Commit changes**.
- Проверить: обновить страницу сайта с очисткой кэша (`Ctrl+F5`).

## Если что-то пошло не так

| Симптом | Причина | Решение |
|---|---|---|
| Ошибка 404 на сайте | Pages не включён или выбрана не та ветка/папка | Settings → Pages: Source `Deploy from a branch`, branch `main`, `/ (root)` |
| Белый экран | Не загрузились `js/` или `css/` (часто — файлы внутри лишней папки) | Проверить, что `index.html` в корне репозитория, а `js/app.min.js` — в папке `js` |
| Нет стилей, «голый» текст | Не загрузился `css/app.css` | Загрузить папку `css` заново |
| Памятки не открываются | Не загружен `assets/memos` | Загрузить папку `assets` целиком |
| Pages недоступен | Репозиторий приватный | Сделать публичным (Settings → General → Danger Zone → Change visibility) или использовать Cloudflare Pages |
| Изменения не видны | Кэш браузера или Pages ещё собирается | Подождать 2 минуты, обновить с `Ctrl+F5` |
| Ссылка открывается, но в конце `/doctor-catalog/` не работает демо | Не добавлен `?demo=1#/home` | Открыть с этим суффиксом или войти по коду |

## Альтернативы GitHub Pages

| Платформа | Плюсы | Как |
|---|---|---|
| **Netlify** | Ссылка сразу, приватность, формы | <https://app.netlify.com/drop> → перетащить папку сайта → войти/зарегистрироваться |
| **Cloudflare Pages** | Свой домен, много запросов | Dashboard → Workers & Pages → Create → Pages → Upload assets |
| **Свой сервер** | Полный контроль, домен компании | Любой статический хостинг (nginx/Apache/VPS), загрузить папку по FTP/SFTP |

Для всех вариантов подходит та же папка сайта: все пути относительные.
